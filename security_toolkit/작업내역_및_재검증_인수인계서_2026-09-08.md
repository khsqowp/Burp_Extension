# Security Toolkit 작업 내역 및 재검증 인수인계서

## 1 문서 목적

이 문서는 2026년 9월 7일부터 8일까지 수행한 Security Toolkit, Scanner Core, Burp Extension 및 오프라인 배포 개선사항을 다른 개발자나 검증 에이전트가 독립적으로 재검토할 수 있도록 정리한 인수인계 자료다.

현재 판정은 다음과 같다.

- 동일 CPU 아키텍처의 준비 PC에서 Docker 이미지와 Burp JAR를 만든 뒤 내부망 PC로 반입하는 운영 방식은 검증됐다.
- 내부망 실행 중에는 패키지, 규칙 또는 페이로드를 인터넷에서 내려받지 않는다.
- 실제 대상 진단은 GET, HEAD, OPTIONS로 제한한 저부하 진단을 기준으로 검증했다.
- 수정 후 세 개의 독립 검토에서 재현 가능한 Block 등급 결함은 남지 않았다.
- 인터넷이 전혀 없는 새 PC에서 소스부터 Docker 이미지와 JAR를 최초 빌드하는 기능은 제공하지 않는다.

## 3 신규 안전 진단 기능

### 3.1 추가 모듈

| 모듈 | 목적 | 기본 네트워크 동작 |
|---|---|---|
| `error_page_disclosure` | Nginx, Tomcat 등 기본 오류 페이지 및 제품 정보 노출 점검 | 임의의 존재하지 않는 경로에 GET 1회, HEAD 1회 |
| `http_methods` | OPTIONS 응답의 위험 메서드 허용 여부 점검 | OPTIONS 1회 |
| `directory_listing` | 디렉터리 목록 노출 징후 점검 | GET 1회 |
| `server_header` | Server, X-Powered-By 등 제품 정보 노출 점검 | HEAD 1회 |
| `security_headers` | CSP 등 브라우저 보안 헤더 누락 또는 약한 설정 점검 | HEAD 1회 |
| `subdomain_discovery` | 제한된 로컬 후보 목록을 이용한 서브도메인 DNS 탐색 | 시스템 DNS, 최대 후보 25개 |
| `virtual_host_isolation` | 동일 IP 서브도메인의 Host 분리 상태 점검 | HTTP HEAD, 최대 후보 5개와 랜덤 Host 1개 |

`directory_listing` 표의 마지막 열에 표시된 GET 요청은 응답 본문을 최대 256 KiB까지만 보존한다.

### 3.2 안전 경계

- 허용 HTTP 메서드: GET, HEAD, OPTIONS
- 리다이렉트 자동 추적: 비활성화
- 쿠키 및 인증정보 자동 전송: 비활성화
- HTTP 환경 프록시 사용: 비활성화
- OAST, Collaborator, Interactsh, Webhook, 텔레메트리: 사용하지 않음
- 자동 규칙 업데이트: 비활성화
- 안전 규칙 파일은 허용 목록 및 SHA-256으로 검증
- 서브도메인 후보 기본 20개, 최대 25개
- 가상 호스트 요청은 동시성 1, 요청 사이 1초
- HTTPS Host와 SNI를 혼합하는 검사는 안전 기본 모드에서 실행하지 않음
- 동일 IP 사용 자체는 취약점이 아니므로 참고 관찰로 분리
- 등록되지 않은 임의 Host가 보호 대상과 같은 응답을 반환할 때만 취약 가능성으로 분류

## 4 Burp Extension 개선

### 4.1 결과 화면

- 결과 영역을 세로 `JSplitPane`으로 변경했다.
- 상단은 가공된 결과, 하단은 RAW 결과다.
- 사용자가 구분선을 드래그해 두 영역 높이를 조절할 수 있다.
- RAW에는 Task별 `result`, `stderr`, `meta`가 표시된다.
- 발견된 이슈에는 심각도, 진단 내용, 예상 피해 한 문장이 표시된다.
- 취약점으로 단정하지 않는 서브도메인 등은 참고 관찰로 표시한다.
- 실패한 Task의 부분 결과는 정상 관찰 결과처럼 상단에 표시하지 않는다.

### 4.2 실행 안정성

- 한 번에 하나의 Scan만 실행하도록 중복 실행을 차단했다.
- 컨텍스트 메뉴 연속 실행으로 로그, RAW, 요약 및 중지 대상이 혼합되는 경로를 차단했다.
- Scan ID 발급 전에 중지를 누르면 중지 예약을 기록하고 ID 발급 직후 중지한다.
- Task polling 제한시간은 10분이다.
- `pending`, `running`, `completed`, `failed`, `cancelled` 외 상태와 status 누락은 오류로 처리한다.
- polling 또는 파싱 오류 발생 시 같은 Scanner API 연결로 서버 Scan 중지를 재시도한다.
- 실행 중 API 설정이 변경돼도 현재 Scan은 시작 시점의 연결 정보를 계속 사용한다.
- 진행률은 실제 도구가 세부 진행률을 제공하지 않는 경우 시간 기반 근사값이며, Task 종료 시 실제 완료 구간으로 보정된다.

### 4.3 외부 전송 차단

- Scanner API 주소는 `http://127.0.0.1:<port>`, `http://localhost:<port>`, `http://[::1]:<port>`만 허용한다.
- Java API 요청은 `Proxy.NO_PROXY`를 사용한다.
- HTTP History Bridge도 기존과 같이 127.0.0.1로만 전송한다.

- `burp_extension/src/main/java/proxyscanner/burpext/SecurityToolkitPanel.java`
- `burp_extension/src/main/java/proxyscanner/burpext/SecurityToolkitClient.java`
- `burp_extension/src/main/java/proxyscanner/burpext/SecurityToolkitSettings.java`

## 5 RAW 기록 및 파이프라인 무결성

### 5.1 Task별 원본 분리

기존에는 같은 Scan에서 같은 모듈을 다시 실행하면 `{module}.json` 파일이 덮어써졌다. 현재는 다음 형식을 사용한다.

```text
{module}.{task-id}.json
{module}.{task-id}.stderr.txt
{module}.{task-id}.meta.json
```

실제 동일 Scan에서 `server_header`를 두 번 실행해 서로 다른 Task ID와 파일에 저장되고 각 `/tasks/{id}/raw`가 해당 Task의 결과를 반환하는 것을 확인했다.

### 5.2 레거시 결과 호환

- Task ID 형식 파일이 하나도 없을 때만 기존 `{module}.*` 파일을 일괄 조회한다.
- 신규 meta와 과거 RAW 또는 stderr가 혼합되는 suffix별 개별 fallback은 제거했다.

### 5.3 오류 처리

- 도구 실행 후 `parse_result`가 예외를 발생시켜도 이미 수집한 stdout, stderr, meta를 보존한다.
- RAW, stderr, Finding, Technology 저장 또는 후처리 중 예외가 발생해도 Task를 FAILED로 종료한다.
- 진행 중 Task가 남은 Scan은 `clean`이 아닌 `incomplete`로 요약한다.
- 취소된 Scan에는 새 Task를 등록하지 않으며 API는 HTTP 409를 반환한다.

## 7 오프라인 배포 개선

### 7.1 이미지 내장 항목

- Scanner Core 소스와 Python 의존 패키지
- ffuf 2.1.0
- gobuster 3.6.0
- Nmap 및 OpenSSL
- 안전 HTTP 규칙 묶음
- ffuf와 gobuster 기본 `common.txt`
- Default Content용 Web-Servers 목록
- JWT용 `scraped-JWT-secrets.txt`
- 해시 분석용 `10k-most-common.txt`
- Directory Traversal용 검토 대상 Intruder 데이터
- 로컬 CVE 및 EOL seed 데이터

대형 SecLists 및 PayloadsAllTheThings 저장소 전체는 실행 이미지에 포함하지 않는다. 등록된 기본 기능이 사용하는 최소 파일만 포함해 미검토 페이로드 유입과 이미지 비대화를 줄였다.

### 7.2 오프라인 번들 구성

```text
offline\bundle\
  scanner-core-image.tar
  burp-history-bridge.jar
  docker-compose.yml
  docker-compose.offline.yml
  SHA256SUMS.txt
```

- `Export-OfflineBundle.ps1`: 이미지 저장, JAR와 Compose 복사, SHA-256 생성
- `Start-Offline.ps1`: 해시 검증, `docker load`, `pull_policy: never`, `--no-build` 기동
- 실행 결과는 번들 외부 `offline\runtime-data`에 저장
- Export 시 과거 bundle의 scanner-data는 `security_toolkit\scanner-data\offline-bundle-preserved-*`로 이동해 보존
- 최종 배포 bundle에는 과거 Scan DB, 로그, 결과 파일을 포함하지 않음

### 7.3 외부망 의존 구분

| 단계 | 인터넷 필요 여부 | 비고 |
|---|---|---|
| 준비 PC에서 Docker 최초 빌드 | 필요 | Docker base image, APT, PyPI, GitHub 다운로드 |
| 준비 PC에서 Maven 최초 빌드 | 필요 | Montoya API, JUnit, Maven plugin 다운로드 |
| 완성 이미지 TAR를 내부망 Docker에 load | 불필요 | 로컬 TAR 사용 |
| 내부망 Scanner Core 실행 | 불필요 | 내부 대상 및 내부 DNS 통신만 사용 |
| 완성 Burp JAR 로드 및 실행 | 불필요 | 런타임 Maven 접근 없음 |

## 9 독립 에이전트 검토 결과

### 9.1 오프라인 의존성 감사

초기 지적:

- 이미지 단독에는 wordlist가 없었음
- 일부 urllib 및 Java 연결이 환경 프록시를 사용할 수 있었음
- Scanner API 주소를 외부 주소로 설정할 수 있었음
- 번들에 이전 scanner-data가 남을 수 있었음

수정 후 판정:

- 동일 CPU 아키텍처의 내부망 런타임에 Block 결함 없음
- 최소 데이터 이미지 내장 확인
- NO_PROXY 및 Java 직접 연결 확인
- SHA-256, `pull_policy: never`, `--no-build` 확인
- 번들에서 이전 결과와 DB 제거 확인

### 9.2 Burp Extension 감사

초기 지적:

- 동시 Scan 혼합 및 잘못된 중지 가능성
- 무한 polling 및 알 수 없는 상태의 양호 오판
- malformed RAW가 전체 Scan을 중단할 가능성
- Scan ID 발급 전 Stop race
- 통신 오류 후 고아 Task 가능성
- 실행 중 API 주소 변경 시 다른 API로 polling할 가능성

수정 후 판정:

- Maven 10개 테스트 통과
- 동일 실행 Client 고정 및 예외 후 stop 재시도 확인
- 남은 Block 등급 결함 없음

### 9.3 Scanner 파이프라인 감사

초기 지적:

- 같은 모듈 반복 실행 시 RAW 덮어쓰기
- parse_result 예외 시 stdout과 stderr 유실
- 저장 예외 시 RUNNING 고착
- 진행 중 Scan의 clean 오판
- 취소된 Scan에 Task 추가 가능
- 신규 파일과 레거시 RAW 혼합

수정 후 판정:

- Task별 파일 분리 및 조회 확인

## 12 남은 한계와 미검증 범위

- 완전히 빈 PC에서 인터넷 없이 소스부터 신규 빌드하는 기능은 없다. 준비 PC에서 만든 이미지 TAR와 JAR가 필요하다.
- 현재 bundle은 빌드한 Docker 이미지의 CPU 아키텍처에 종속된다. amd64와 arm64는 별도 제작이 필요하다.
- 내부 DNS가 없는 폐쇄망에서는 도메인 및 서브도메인 탐색을 사용할 수 없다. IP 기반 진단은 가능하다.
- 번들 내부 SHA-256은 우발적 손상은 검출하지만 공격자가 파일과 manifest를 함께 바꾸는 경우까지 방어하는 전자서명은 아니다.
- 기존 테스트 11개는 외부 서버 또는 삭제된 Claude 임시 fixture 의존 때문에 완전 오프라인 회귀 테스트로 사용할 수 없다. 별도의 self-contained fixture 전환 작업이 필요하다.
- 실제 Burp Suite 프로세스에 JAR를 로드한 사람의 클릭 기반 시각 검증은 자동 Swing flow test와 별개로 한 번 더 수행하는 것이 좋다.
- 네트워크 단절 상태에서 서버 stop 요청 자체가 전달되지 않으면 Extension이 원격 프로세스 종료를 보장할 수 없다. 코드는 오류를 표시하고 중지를 재시도한다.

## 13 최종 검토 판정 기준

다른 검토자는 다음 조건을 모두 만족할 때만 승인해야 한다.

- Burp Maven 테스트 10개가 모두 통과한다.
- 무인터넷 핵심 회귀 테스트 5개가 모두 통과한다.
- 오프라인 bundle 해시가 일치한다.
- bundle에 scanner DB, 로그 및 과거 결과가 없다.
- 동일 모듈 반복 실행 결과가 Task ID별로 분리된다.
- 실패 및 파싱 오류에서도 RAW, stderr, meta가 보존된다.
- 진행 중이거나 일부 실패한 Scan을 전체 양호로 표시하지 않는다.
- Burp 화면의 상단 가공 결과와 하단 RAW가 실제 실행 결과와 일치한다.
- 실제 대상 시험은 사전 합의된 요청 수, 메서드 및 속도를 초과하지 않는다.
